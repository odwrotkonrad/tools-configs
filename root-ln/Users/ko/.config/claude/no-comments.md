## AI-Generated Code

> [!CAUTION]
> # 🛑 ZERO COMMENTS. NON-NEGOTIABLE. 🛑
>
> **NEVER add comments to AI-generated code. EVER.** This applies to **every
> file type** — code, config, YAML, TOML, JSON5, Makefiles, shell, dotfiles,
> **everything**. None, zero, nothing — no explanatory comments, section
> markers, labeled-convention comments, header/banner comments, schema notes,
> TODO/FIXME, explanatory docstrings, inline notes, or commented-out code.
>
> **This is a HARD STOP.** Adding a comment is a failure of the task, even if
> the surrounding file is full of comments, even if it "documents" a convention,
> even if it seems helpful. **Helpfulness is not an exception.**
>
> Before writing or editing ANY file, check: *am I about to emit a comment?* If
> yes — **delete it** and put that explanation in **chat** instead. If you ever
> catch yourself having added one, **remove it immediately** without being asked.
>
> The **ONLY** exception: the user, in their **current** request, **explicitly**
> asks for comments using the word "comment" (or equivalent). Silence is not
> permission. The repo convention, a file already having comments, a commenting
> spec/convention doc, or a request to "explain/document/annotate" is **NOT**
> permission. **When in doubt: NO COMMENTS.**
